4. ARQUIVOS CRIADOS — DETALHES
----------------------------------------------------------------

── MODELOS ──────────────────────────────────────────────────

vendor_model.dart
  Representa a farmácia/vendedor no sistema.
  Campos: id, name, ownerName, email, phone, address,
          city, state, zipCode, openingHours, hasDelivery,
          isApproved, isActive, createdAt
  Métodos: toMap(), fromMap(), copyWith(), statusLabel

product_model.dart
  Representa um produto/medicamento da farmácia.
  Campos: id, pharmacyId, name, description, category,
          price, stock, requiresPrescription, isActive, createdAt
  Métodos: toMap(), fromMap(), copyWith(), formattedPrice
  Getters: isAvailable (ativo + estoque > 0)

order_model.dart
  Representa um pedido feito pelo usuário.
  Classes: OrderItem, OrderModel, enum OrderStatus
  Status disponíveis:
    pending     → Aguardando confirmação
    confirmed   → Confirmado
    preparing   → Em preparação
    ready       → Pronto
    delivering  → Saiu para entrega
    delivered   → Entregue
    cancelled   → Cancelado

── PROVIDERS ─────────────────────────────────────────────────

auth_provider.dart (VendorAuthNotifier)
  Gerencia login, cadastro e sessão do vendedor.
  Estado: VendorAuthState (vendor, isLoading, errorMessage)
  Getters: isLoggedIn, isApproved, isPending
  Métodos:
    register() → cria conta com isApproved = false
    login()    → autentica e carrega dados do Firestore
    logout()   → desloga
    refreshVendorStatus() → verifica se foi aprovado

orders_provider.dart (OrdersNotifier)
  Gerencia pedidos da farmácia.
  Métodos:
    loadOrders()           → busca pedidos no Firestore
    updateOrderStatus()    → atualiza status do pedido
    byStatus()             → filtra por status
  Getters: todayOrders, todayRevenue

products_provider.dart (ProductsNotifier)
  Gerencia produtos da farmácia.
  Métodos:
    loadProducts()   → busca produtos no Firestore
    addProduct()     → adiciona produto
    updateProduct()  → edita produto
    updateStock()    → atualiza estoque
    deleteProduct()  → remove produto

── TELAS ─────────────────────────────────────────────────────

splash_screen.dart
  Tela inicial com logo e animação de fade.
  Redireciona para: login | pending | dashboard
  Cor: azul escuro (diferente do app usuário que é verde)

login_screen.dart
  Login com e-mail e senha.
  Após login verifica se está aprovado:
    isApproved = true  → vai para dashboard
    isApproved = false → vai para pending

register_screen.dart
  Cadastro completo da farmácia.
  Campos: nome da farmácia, responsável, e-mail, senha,
          telefone, endereço, cidade, UF, CEP
  Aviso visível: "conta passará por aprovação"
  Após cadastro: vai para pending

pending_screen.dart
  Tela de espera enquanto o admin não aprovou.
  Mostra nome da farmácia cadastrada.
  Botão "Verificar status" chama refreshVendorStatus()
  Botão "Sair da conta"

dashboard_screen.dart
  Painel principal do vendedor.
  Seções:
    - Resumo do dia (novos pedidos, pedidos hoje, faturamento)
    - Alerta de pedidos pendentes
    - Ações rápidas (Pedidos, Produtos, Minha Farmácia, Relatórios)
    - Últimos 5 pedidos com status colorido
  Ação de logout no AppBar
  Pull-to-refresh para atualizar pedidos

6. FLUXO DE APROVAÇÃO DO VENDEDOR
----------------------------------------------------------------

1. Vendedor acessa o app do vendedor
2. Clica em "Cadastrar farmácia"
3. Preenche todos os dados
4. Sistema cria conta no Firebase Auth
5. Salva dados no Firestore com isApproved = false
6. Vendedor vai para tela "Aguardando aprovação"
7. Admin acessa o painel admin
8. Vê a farmácia na lista de "Pendentes"
9. Clica em "Aprovar"
10. Sistema atualiza isApproved = true no Firestore
11. Vendedor clica "Verificar status" ou entra novamente
12. App detecta isApproved = true
13. Vendedor acessa o dashboard normalmente
